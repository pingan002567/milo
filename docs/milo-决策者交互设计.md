# Milo 决策者交互设计（私聊优先）

> 对应《milo-产品方案.md》第五章指挥体系，以及 Console 原型 `prototype/console.html`。  
> 沉淀日期：2026-07-18  
> 范围：**先只做私聊**；群聊 / 任务频道另案。

---

## 1. 一句话原则

**用户是最上层决策者，唯一直属下属是 Conductor；界面可长得像办公 IM，协议不能是多人真群聊。**

| 角色 | 对用户的关系 | 交互 |
|---|---|---|
| Conductor | 唯一直属 | 私聊：下达任务、批计划、收请示、看进度摘要 |
| 成员 / 部门 | 隔级下属 | **不可私聊**；可在「组织」巡视只读状态与产物 |
| 成员 ↔ 成员 | 无直连 | 一切经 Conductor 路由 + artifact 交接 |

---

## 2. 为何不用办公软件原样的「群 + 私」

办公软件常见：

- **私聊**：你 ↔ 一个人  
- **群聊**：多人同频道，谁都能插话  

若 Milo 做成成员也能私聊用户、或进真群聊：

- 绕过 Conductor → 汇报关系与 artifact 交接失效  
- 用户重新面对「哪条是最终答案」  
- escalate 变成刷屏，告警稀缺性失效  

因此：

- **借用私聊心智**：只保留「你 ↔ Conductor」  
- **暂不做群聊**；若日后做，做成「任务动态墙」（只读里程碑 + 用户发言仍进 Conductor），不是自由群聊  

更贴切的类比：你 ↔ 秘书（私聊），而不是项目微信群。

## 3. 私聊产品形态（已定）

### 3.1 会话列表

- 分区 **「可对话」**：仅 Conductor（未读数 = 待批请示条数）。  
- 分区 **「下属（不可私聊）」**：成员/部门灰显；点击提示「经 Conductor 汇报」，不打开会话。  
- 组织切换挂在列表顶（当前组织上下文），不引入多 Conductor 私聊（一组织一 Conductor）。

### 3.2 私聊主会话（你 ↔ Conductor）

同一条时间线承载四类消息（不另开「运行态」侧栏抢注意力）：

| 类型 | 形态 | 通道语义 |
|---|---|---|
| 普通对话 | 气泡 | 下达任务、澄清、闲置问答 |
| 计划前置 | 卡片 + 批准/调整 | 长任务门禁 |
| **请示** | 阻塞卡片（见 §4） | 阻塞通道 · 推送感 |
| 进度 | 居中系统条（轻量） | 进度通道 · 不弹窗 |

成员级细节不进气泡正文；需要时链到 Trace / 组织巡视。

### 3.3 用户介入三档（私聊语境下）

| 档位 | 在私聊里怎么做 | 默认 |
|---|---|---|
| L1 批示 | 只回请示卡、批计划 | ✓ 默认 |
| L2 巡视 | 离开私聊 → 组织图 / Trace 只读 | 按需 |
| L3 干预 | 私聊里说「改派 / 暂停 / 加约束」，由 Conductor 执行 | 高级 |

不做：用户 ↔ 成员双人会话。

---

## 4. 请示卡片标准结构

每条阻塞请示（嵌在私聊里）固定五段：

1. **要你决定什么**（一句话标题）  
2. **标签**：`需要你决定` + 原因（escalate / 里程碑门禁 / `ask_user` 路由）+ `task_id`  
3. **为何轮到你**（策略命中 / 权限收敛 / 门禁）  
4. **最小上下文**（关键事实 + artifact 引用，禁止贴全文日志）  
5. **选项**：2–3 个主操作；可选「驳回 / 先改计划」  

批完卡片变为「已回复」，后续进度用系统条回写，不连环追问（除非再次 escalate）。

**健康指标**（沿用产品方案）：单任务打扰次数、override 率、待批队列时长。过高 → 收紧 escalation / permissions，而不是加通知。

---

## 5. 与既有设计的咬合

| 既有概念 | 在私聊里的落点 |
|---|---|
| Conductor 唯一对话入口 | 唯一可私聊对象 |
| 双通道汇报 | 请示卡 = 阻塞；系统条 = 进度 |
| SAT 三槽位 | 进度条或 Trace 下钻，不上浮为碎聊 |
| action guards / escalation | 决定「何时出现请示卡」 |
| 计划前置授权 | 私聊内计划卡片 |
| org.yaml 路由 `default: ask_user` | 生成请示卡 |
| 成员不可见（可下钻） | 会话列表灰显 + 组织巡视 |

## 6. 明确非目标（本阶段）

- 群聊 / 任务频道 / @成员  
- 用户与成员的私聊或「代发私聊」入口（日后若做 consult，须另开设计：仍挂在 Conductor 线程下）  
- 把汇报关系画成可编辑连线  
- 成员过程日志流进私聊气泡
